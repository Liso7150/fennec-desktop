# Changelog

All notable changes to fennec-desktop, the suite's native Rust desktop application —
the one native window in the product.

The sections below carry the published tag each change actually shipped in
(`Liso7150/fennec-desktop`, `v0.3.0` … `v1.0.0`). An earlier revision of this file
numbered the same history on a 1.x/2.x ladder that was never published; those tags
still exist locally (`v1.0.0` … `v2.0.0`) and each points at the same commit as a
published `v0.x` tag — except local `v1.0.0`, `v1.1.0` and `v1.2.0`, which mark
pre-release commits that shipped inside published `v0.3.0`. The first release here
was `0.3.0`; `0.1.0` and `0.2.0` were never published. Releases up to and including
`0.9.0` were Electron packages (the `0.9.0` note calls it the last Electron build);
everything after that tag is the native rewrite described below. Dates are the tag
publish dates.

## [1.0.0] - 2026-11-24
Version 1.0.0 is the current release.
Measured on the working tree: **59 tests passed / 0 failed
across 4 suites** (`cargo test --offline --features gui`). Counts come from
`benchmarks/artifacts/hub/RESULTS.json` (updated 2026-11-24T13:27:28Z) and are
generated by the hub (`python benchmarks/results.py` in the suite root), not
hand-maintained. A Windows release build still needs `fxc.exe` from the Windows SDK
to compile shaders.

### Added
- The app is native Rust/GPUI: no Electron, no Node runtime, no web view. The gpui
  shell (`src/gui_main.rs`, bin `fennec-desktop-gui`, `cargo build --features gui`)
  is the desktop app; the egui binary `fennec-desktop` is the shell it replaced, kept
  buildable for A/B
- Full native feature parity — every supported handler ported, and the three-pane
  coding-agent UI in `src/gui_main.rs`: task list, conversation pane, context rail
- Shared widgets: the UI consumes the `fennec-ui` crate, so a rule fixed once shows
  up on both surfaces
- Resume after restart. A run persisted as `Running` used to be demoted to `Idle` and
  left there, freezing a question that was still open. Now `load()` collects restored
  runs carrying a core session id, `resume_runs()` asks the service
  (`/api/agent/sessions`) which it still holds, and those are re-polled.
  `CoreEvent::Replay` clears only what the previous window watched after the prompt,
  and only once the service has answered, so a pruned session leaves its history
  instead of an empty row. Answered approvals survive the replay.
- Git-diff review on a write row, the Plan checklist from the loop's `plan` step,
  the queue strip wiring,
  shortened folded rows, written files delivered as cards grouped by the answer they
  serve, and a right panel listing inspectable subagents/processes/skills/artifacts/
  web links/sources
- Collections bounded in long sessions: most recent 100 tasks, 50 timelines,
  200 `seen_at` entries, oldest evicted first (`src/main.rs`, egui shell)
- Environment rail shows the outlet state the core actually reports; README hero
  published

### Changed
- Coding tasks route through the supervised core on `127.0.0.1:8787`; the Rust
  service on `:8788` is auxiliary/chat only and never a coding fallback
- Context inspector redesigned to match the PWA layout
- Reuse instead of re-implementation: `fennec-client` and `fennec-economy` come from
  the fennec-core workspace and the sibling repo, the engine and CLI from their own
  repos
- Crate moved to Rust edition 2024 with `rust-version = 1.85`; eframe upgraded
  0.27 → 0.37; the macOS toolchain unpinned
- Event handling and the main loop expanded (`src/events.rs`); scroll area uses
  `clamped_offset()` instead of the deprecated `offset()` heuristic
- CI builds check out fennec-economy alongside fennec-core
- The no-backend status lines tell the user to start the engine with
  `fennec serve --auto-tier` (GPU offload), not bare `fennec serve`
- The Electron leftovers and the redundant config/engine modules are gone; the legacy
  JS/TS source stays on the `legacy-electron` branch
- Settings dialog matches the PWA layout: the Connection tab is deleted (engine and
  agent endpoints are loopback-only), leaving Appearance, GitHub, Obsidian, Behavior,
  Advanced, Integrations; Save persists font size only
- Fox mark replaces the shield icon, embedded in the exe via `build.rs` +
  `build/fennec-desktop.rc`

### Removed
- `src/updater.rs` and its `pub mod`: the module checked `Liso7150/fennec-desktop`
  GitHub releases (SHA-256-verified downloads, stable/experimental channels) but no UI
  element ever called it. `reqwest`, `sha2`, `hex` and `tokio` leave `Cargo.toml` with
  it; the update path is the environment-setup hub's plan, which fetches every
  checkout with git

### Fixed
- Coding routing now requires a complete protocol-v1 core capability contract.
  Rust-only, partial, malformed or unavailable backends fail closed with an
  actionable core message; queue drain, approval answers and cancellation also
  require live supervised capability, and saved URLs migrate by capability
- Approval timeouts end the turn without retrying the model, duplicate rejected
  calls stop with `permission_denied`, and the default review window is 15 minutes
- The composer's model chip and the model dropdown name the checkpoint the engine
  actually serves. The shell already read `model` from the engine's `/health` reply
  into its polled `EngineState`, but drew `self.model` (whatever was last chosen) —
  so with `wsp-qwen35-0.8b` running the chip claimed a model nothing was answering
  for. `active_model()` now prefers the served id and falls back to the stored choice
  when no engine is up, and the served id leads the dropdown (`src/gui_main.rs`,
  2026-11-24)
- A prompt sent while the engine is cold is no longer refused: `/api/agent/start`
  answers 503 until the model listens, so the prompt waits in the app and the 2 s
  status poll re-sends it once the engine answers, inside a 300 s window; past it the
  text goes back to the composer. The queue holds one prompt.
- The warm-up ask is no longer treated as an error the app can see — the route's
  dead-engine probe is removed in fennec-core
- Text inputs that lost clicks inside scroll containers (the Browser address field,
  the rail's Search filter) now take focus via a wrapper mouse-down handler — the
  editor's own hitbox alone never received the click there
- All four dialogs (Settings, Review diff, Edit queued task, Rename Task) pass
  `DialogEntrance::None`, so the surface paints opaque in one frame instead of fading
  in transparent over the chat
- Long task titles truncate so the rename/delete buttons stay reachable; a11y element
  ids are unique inside GUI loops, preventing the duplicate-node crash
- Dictation feedback improved, and the Send button says what the shortcut is:
  `{Cmd,Ctrl}+Enter sends`
- Reopening the app no longer forgets what a run did: selecting a session asks the
  loop for the steps it kept and replays them, prompt included

## [0.4.0] - 2026-11-11

### Added
- Orphaned engine processes swept on stop and quit
- Host expert pool defaulted to 4 GB: gives back the ~9 GB between the engine's
  13 GB default and 4 GB, and costs ~6 % decode (13.95 vs 14.88 tok/s measured
  2026-11-10 on this machine). 2 GB falls off a cliff at 6.27 tok/s, so the
  saving stops at 4
- The GPU is used on backend auto when a Vulkan loader is present
- The desktop agent payload is compacted, and the saving shows in the header

### Changed
- CI granted `contents:write` so tag builds can publish releases

## [0.3.0] - 2026-11-10

The first published release. It carries the pre-tag history below.

### Changed
- Rebrand the desktop app to Fennec Desktop
- No drive letter assumed: every root defaults to the user home
- Speech input, read-aloud, vision, file attachments and GitHub updates
- The sidecar runs on any Python, and releases are checked on start and use
- Max tokens passed to serve as `--ngen`, the flag the engine accepts
- The engine starts on demand and the app stops only the one it owns
- Icon upscaled to 512×512 for macOS packaging

### Fixed
- The OpenVINO NPU compile artifact ignored, so it cannot reach a release diff
